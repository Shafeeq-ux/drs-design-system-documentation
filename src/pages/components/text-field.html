Text field

Lets people enter and edit a short piece of text, such as a name, email, ZIP code or VIN. The same box is used for dropdown selects.

4 published Figma sets.aec-field

There are two published styles. Standard has the label above an outlined box and is the default for forms. Material has a floating label inside a filled box, for compact layouts. Both support prefix and suffix content, icons, assistive text and a dropdown type.

Use a text field when people need to type an answer. If there are only a few options to choose from, use radio buttons or a dropdown instead.

Standard

The label sits above the box, so it stays visible while people type. Use this style for checkout and credit application forms.

Dropdown

Use type=dropdown for a short list of options. It's a native <select> with a trailing caret icon.

Prefix, suffix and icons

Use a prefix or suffix for a unit, such as $ or miles, so people don't have to type it. Use a leading icon only when it helps people recognise the field.

Material

The label sits inside the box as a placeholder and floats up when the field has focus or a value. The input needs placeholder=" " and must come before its label in the markup. Don't mix standard and material fields in one form.

States

Every field has default (empty), hover, focus, filled, error and disabled states. The colours come from the active brand's input tokens (--aec-input-standard-outlined-color-* and --aec-input-material-filled-color-*), so switch the brand in the header to see how each one changes. Focus changes the border to the active colour. Keyboard focus also adds a 2px focus/default ring outside the box.

In the material row, the label floats when the field has a value or real keyboard focus. The forced focus column shows the border only.

Assistive text

Assistive text sits below the box. Use the default type for hints, and the error, success and warning types for feedback. Feedback types always have an icon, so they don't rely on colour alone.

Usage

Labels and hints

Field width

Units and read-only values

  • Use the right type, inputmode and autocomplete so mobile keyboards and autofill work.
  • Validate when the field loses focus or the form is submitted, not on every keystroke.
  • Keep the value people typed when you show an error, so they can correct it.
  • Use one style per form. Standard is the default; use material only for compact layouts such as a filter bar.

Content

Write in sentence case. Brands that show uppercase labels apply it through their typography tokens.

  • Labels are short nouns that say what to enter: Email address, ZIP code. Don't end them with a colon.
  • Placeholders are optional examples of the format, such as name@example.com. Never put the only instructions there.
  • Helper text explains why you need the information or what format to use, in one short sentence.
  • Error messages say what went wrong and how to fix it, without blame: Enter a 5-digit ZIP code, not Invalid ZIP.

Accessibility

Labels WCAG 1.3.1 · 3.3.2

Every input needs a <label for>. Required fields also get the required attribute. The visual * is aria-hidden.

Errors WCAG 3.3.1

Set aria-invalid="true" and connect the message with aria-describedby. Errors are shown with an icon and text, not colour alone.

Focus WCAG 2.4.7

Focus changes the border to the brand's active colour and adds the 2px focus ring for keyboard users.

Input purpose WCAG 1.3.5

Use autocomplete values (given-name, email, postal-code, tel) on personal-data fields.

Keyboard WCAG 2.1.1

Fields are native inputs, so Tab and Shift+Tab move between them. Dropdowns use a native <select>, so arrow keys and type-ahead work. Don't add a positive tabindex.

Helper text WCAG 1.3.1

Connect helper text with aria-describedby so screen readers read it after the label. When an error appears, add the error's id to the same attribute.

Text contrast WCAG 1.4.3

Labels, values and assistive text need at least 4.5:1 against their background. These ratios are measured live in the active brand. Disabled fields are exempt. Placeholder text should also reach 4.5:1, but the browser doesn't expose its colour, so check it in the brand file (--aec-input-*-color-text-prompt).

  • Material Outlined, Material Plain and Standard Filled exist in Figma as hidden sets and aren't documented here.
