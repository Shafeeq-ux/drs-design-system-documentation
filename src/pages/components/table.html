Table

Organises data into rows and columns so it can be scanned and compared, for example a payment breakdown or saved deals.

Legacy Figma component, remapped.aec-table

Use a table when people need to compare values across several items, such as the status and monthly payment of each saved deal. A table can have sortable columns, selectable rows and three densities. It has no brand tokens of its own: it uses the semantic --aec-color-* tokens and the body-2 type style, so it still follows the active brand. For a short list of label and value pairs, such as a price summary, a plain list is often easier to read.

Usage

  • Use a table for data people compare across rows. Don't use one to lay out a page or a form.
  • Put the column people scan first, usually the item name, on the left.
  • Keep row actions, such as View deal, in the last column.

Do / don't: usage

Content

Column headers are labels, not sentences. Use one or two words, in sentence case, and put units in the header rather than in every cell where you can, for example "Term (months)". Format values the same way down a column: the same currency format, the same date format and the same number of decimal places.

Accessibility

Semantics WCAG 1.3.1

Use a real <table> with a <caption> and scope on header cells. Sorted columns use aria-sort.

Headers and scope WCAG 1.3.1

Use <th scope="col"> for column headers. If the first cell of each row names the row, such as the vehicle, make it <th scope="row">. A screen reader then reads "2025 Equinox LT, Monthly, $489".

Sorting WCAG 4.1.2

Put a <button class="aec-table__sort"> inside the header cell, and set aria-sort="ascending" or "descending" on the <th> of the sorted column only.

Selection WCAG 4.1.2

Each row checkbox needs a label that names the row, such as "Select 2025 Equinox". The header checkbox selects all rows.

Scrolling WCAG 1.4.10

Wide tables scroll inside .aec-table-wrap. Give the wrapper tabindex="0" and a label so keyboard users can scroll it.

Text contrast WCAG 1.4.3

Text needs at least 4.5:1 against its row. These ratios are measured live in the active brand, using the same tokens as the table.

Figma notes

Differences found in the Figma library, for the design team to review:

  • This is a legacy component, with an off-palette grey scale (#f1f1f3, #60616c, #e4e4e7), Space/Padding/* variables and an older checkbox. The code maps it to current tokens and uses the current checkbox.
  • The size order is inconsistent: Small controls are taller than Default ones.
  • Figma has no hover or selected row states. The code adds them.
  • There are no table tokens in the brand files, so the table looks the same in every brand apart from its semantic colours and type.
  • There are typos in Figma ("Checkbox Dropdawn", "Expended").
