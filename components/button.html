Button

Triggers an action, such as submitting a form, moving to the next checkout step or opening a dialog.

11 Figma component sets.aec-btn

A button tells people what will happen when they press it. Buttons come in five emphasis colours (primary, secondary, neutral, inverse, destructive), three styles (filled, outline, plain) and an inline text style. Use buttons for actions. To take someone to another page, use a link.

Variants

Choose the emphasis by how important the action is, not by how it looks. Use one primary action per view.

Primary

The main action on the page, for example Continue to payment. Use one per view.

Secondary

Strong but neutral actions next to a primary, or the main action where blue would compete with content.

Neutral

Low-emphasis utility actions. It looks the same as secondary, and is kept as its own set for parity with Figma.

Standard

A white button with a blue outline. Use it on tinted or image backgrounds where an outline alone would disappear.

Destructive

Actions that remove or cancel something and can't easily be undone, for example Remove trade-in.

Inverse

For dark surfaces such as the header, hero banners and snackbars.

Inline

A text-only button inside a sentence, card or table row. It is 24px tall and has no padding.

With icons

Icons are optional, sit on either side of the label (16px) and must reinforce the label, not replace it. Use the icon button for icon-only actions.

States

Hover and pressed share one colour in Figma. Keyboard focus adds a 2px focus/default ring, 2px outside the button. Try tabbing to the buttons below.

Sizes

Large (48px) is the Figma size and the default. Medium and small are added in code for dense layouts. In Figma all three sizes are currently 48px.

Add .aec-btn--block to make a button fill its container. This is useful for the sticky action bar on mobile.

Grouping

Wrap related buttons in .aec-btn-group (16px gap, selectable-gap-l). Put the primary action last, on the right, on desktop. On mobile, stack full-width buttons with the primary action on top.

Do
Pair one primary with a lower-emphasis option.
Don't
Don't place two primary buttons side by side, because people can't tell which is the main action.

Content

  • Start with a verb that describes the outcome: Continue to payment, Schedule test drive.
  • Keep it short: one to three words when possible.
  • Use sentence case and no end punctuation.
  • Be specific: Remove trade-in is clearer than Remove in a confirmation dialog.

Accessibility

Use the right element WCAG 4.1.2

Use <button type="button"> for actions and <a href> for navigation. A link styled as a button still needs .aec-btn and an href.

Target size WCAG 2.5.8

The default 48px height exceeds the 24×24px minimum. Inline buttons are 24px tall, so leave space around them.

Focus visible WCAG 2.4.7

Every button shows a 2px focus/default ring on :focus-visible. Don't remove it.

Contrast WCAG 1.4.3

White on primary/default is 4.53:1 and white on secondary/default is 15:1. Disabled buttons are exempt, but you should still explain why an action is unavailable.

Disabled buttons

Prefer keeping the button enabled and showing validation messages. If you must disable it, use disabled, or aria-disabled="true" if it needs to stay focusable so it can show a tooltip.

Icon-only WCAG 1.1.1

Give decorative icons inside labelled buttons aria-hidden="true". Icon-only buttons need aria-label.

Figma notes

Differences found in the Figma library, for the design team to review:

  • The size variants (large, medium, small) are all 48px tall. The code adds 40px and 32px sizes.
  • Neutral's pressed state goes back to the default colour (#262626). The code uses the hover colour for pressed, as the other sets do.
  • Destructive has no hover change in Figma, so the code doesn't add one either.
  • Button – Standard's description says "dark text with gray border", but the design is blue.
  • Inline Button – Neutral is blue, the same as Primary.
  • Colours in the components are raw hex values, not linked to the colour styles.
