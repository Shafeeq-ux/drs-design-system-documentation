Modal & sheet

Focuses attention on a task or message in a layer that blocks the page behind it. It comes in three forms: a centred modal, a right sheet and a bottom sheet.

9 Figma variantsdialog.aec-modal

A modal interrupts. Nothing else on the page can be used until it is closed, so use one only when the person must deal with something now: confirming that they want to remove a trade-in, or a short task such as choosing delivery. Use a right sheet for supporting detail that people read next to the page, such as a payment breakdown. On small screens a modal opens as a bottom sheet. For messages that don't need an answer, use a snackbar or an alert.

Types

Choose the type by what the content is for. Modals and sheets have no interactive states of their own. The buttons inside them follow the button states.

Modal

Centred on the page. For confirmations and short, focused tasks. Small suits a message and two buttons, medium a short form, large a comparison.

Right sheet

Slides in from the right and fills the height of the screen. For supporting detail that relates to the page, such as a payment breakdown or vehicle specs.

Bottom sheet

Slides up from the bottom, full width. For quick choices on mobile. On screens narrower than 768px, every modal opens as a bottom sheet.

Usage

  • Use a modal to confirm destructive or important actions, and for short focused tasks.
  • Use a right sheet for supporting detail that people compare with the page, such as a payment breakdown.
  • Don't stack modals, and don't open them without a user action.

Do / don't: usage

Content

Write the title as the question or task, in sentence case, in a few words. The body says what will happen, with the numbers that matter. Button labels repeat the verb from the title, so people can choose without reading the body again.

Accessibility

Native dialog WCAG 2.4.3 · 2.1.2

Built on <dialog> with showModal(). Focus is trapped in the dialog, the page behind is inert, Esc closes it, and focus returns to the trigger afterwards.

Name WCAG 4.1.2

Point aria-labelledby at the title. If the body is a short message, point aria-describedby at it too, so it is read out when the dialog opens.

Initial focus WCAG 2.4.3

Focus moves to the first focusable element, usually the close button. For a destructive confirmation, put autofocus on the safe action, such as "Keep trade-in", so Enter doesn't remove anything by mistake.

Keyboard WCAG 2.1.1

Tab and Shift+Tab cycle through the controls inside the dialog only. Esc closes it, the same as the close button.

Closing

Clicking the backdrop closes the dialog, except when it has data-static. Use that for forms with unsaved changes.

Motion WCAG 2.3.3

The open animation is turned off when people ask for reduced motion.

Text contrast WCAG 1.4.3

Text needs at least 4.5:1 against the dialog surface. These ratios are measured live in the active brand. For button contrast, see Button.

Figma notes

Differences found in the Figma library, for the design team to review:

  • The content and footer are placeholder slots in Figma.
  • The header divider uses #d2d2d2 or #dedede, neither of which is a token. The code uses border/default.
  • Figma has no shadow or backdrop. The code adds a shadow and backdrop/default.
  • The 20px bold title has no text style. The code uses heading-4.
