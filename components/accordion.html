Accordion

Shows and hides sections of related content, so people can expand only what they need, for example FAQs or the details of a protection plan.

8 Figma variants.aec-accordion

An accordion is a stack of headings. Each heading is a button that opens or closes the section below it. Use it to shorten long pages of optional detail, such as FAQs, coverage terms or a list of documents. Don't use it to hide anything people need to make a decision. To switch between parallel views of the same thing, use tabs.

Default

Each item has a trigger and a panel. A trigger can have a leading icon and a short meta label, such as a count, before the chevron.

Parts and labour for covered components for 5 years or 60,000 miles, plus roadside assistance and rental car reimbursement.

A valid driver's licence, proof of insurance and proof of residence.

Yes, within 3 days or 150 miles under the dealer's exchange policy.

Add data-single to .aec-accordion so that only one section can be open at a time.

States

Each trigger is either collapsed or expanded, and both can be hovered, focused or disabled. The colours come from the active brand's accordion tokens: --aec-accordion-color-* for collapsed and --aec-accordion-color-selected-* for expanded. Switch the brand in the header to see how each one changes. Focus adds a 2px focus/default ring inside the trigger. There is no separate pressed style, so it isn't shown.

Usage

  • Use an accordion for optional, secondary detail that would make the page long, such as FAQs or plan terms.
  • Don't hide critical information, such as pricing or required steps, in a collapsed section.
  • For switching between parallel views, use tabs.

Do / don't: usage

Content

The heading is all people see before they open a section, so it must say what's inside. Write headings as short questions or plain labels, in sentence case. Keep them to one line on mobile where you can. Use the meta label only for a short count or status, such as "3 items" or "Complete".

Accessibility

Structure WCAG 1.3.1

Each trigger is a <button> inside a heading at the right level for the page. Its aria-expanded state and aria-controls point to the panel.

State WCAG 4.1.2

Keep aria-expanded in step with the panel: "true" when it is open, "false" when it is hidden. A screen reader says "Trade-in, button, collapsed". Hide closed panels with hidden, not just visually.

Keyboard WCAG 2.1.1

Tab moves between triggers, and Enter or Space toggles a section. Focus shows a 2px inset ring. Opening a section doesn't move focus.

Panels WCAG 1.3.1

Give each panel role="region" and a label that matches its heading, so it shows up as a landmark. Leave the role out when there are more than six items, to avoid too many landmarks.

Disabled sections

Use disabled on the trigger and say why in the title, for example "(coming soon)". Disabled triggers are skipped by Tab.

Text contrast WCAG 1.4.3

Text needs at least 4.5:1 against its background. These ratios are measured live in the active brand. Disabled triggers are exempt.

Figma notes

Differences found in the Figma library, for the design team to review:

  • All 8 Figma variants look identical: no hover, pressed or disabled styling, and expand=on has no panel. The states above are proposed in code using tokens.
  • The title uses Avenir LT Pro Heavy in pure black (#000). The code uses body-1 bold with the accordion text tokens.
  • The divider is #dedede. The code uses --aec-accordion-color-border-default.
